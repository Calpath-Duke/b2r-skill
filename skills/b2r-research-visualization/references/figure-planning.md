# Scientific Figure Brief：按复杂度规划

只在多步骤、跨区室或需要重构信息的图件中读取。简单插画直接把理解融入工具请求；不强制生成文件、对象 ID、十项表格或 JSON。Brief 是同一份科学内容规划，可为几行文字，也可在审查需要时使用旧结构化记录。

## 一次整理必要内容

用紧凑段落或短列表整理：**用途/主信息；科学对象；关键关系与机制顺序；必要空间与阅读顺序；准确术语/数值；事实/假设边界及用户视觉要求**。只展开影响当前图件的部分。未指定图内语言时一次确定英文标签；原始标识、缩写、数据与明确逐字要求保留，不重写原表。双图共用这份科学内容与标签，只在工具请求中分别加入 Classic/Refined 视觉处理，不复制两套规划。原话与请求分开保存，Brief 在生图前完成。

对象区分细胞、细胞器、蛋白/抗体、药物载荷、化学结构和概念符号。同一对象跨阶段保持可追踪形态/配色；不同产物用形态或标签区分，不能只靠颜色。例如复合物的载荷与释放物相连贯，细胞释放的抗原另用编码。

关系与证据分开理解：
- 组成用汇合/包含；结合体现正确端点与朝向；激活/抑制采用有方向的箭头/T 端点。
- 运输核对起终区室；转化/释放保留前后身份；因果只在材料支持时表达，背景/关联不自动加因果线。
- 用户明确提供、来源陈述、假设/推断和视觉简化各自保留。出处未核验不把所有箭头变成假设；未知的具体机制可保留概念范围，不补靶点、分子、剂量或研究结论。

若局部接触改变科学含义，明确结合端部/表面，而非只写两个对象名称。精确构象需要可靠结构依据。不同时间的细胞整体状态分开，避免将死亡阶段画成另一颗细胞包含于原细胞内。

## 用信息关系选图件结构

先看关系图的形状，而不是主题词：有方向的信号链、按时间推进的阶段、“类别—成员—共同目标”的分类、步骤化研究流程、围绕一个中心的多个领域、跨尺度定位、条件对照还是闭环。选 1 个主结构，必要时组合 1 个辅助结构（如“机制通路 + 多尺度”）。

| 结构 | 适合的信息 | 版式骨架 |
|---|---|---|
| pathway 机制通路 | 信号转导、药物作用、疾病分子机制 | 区室做细泳道（胞外/膜/胞质/核），单一主方向；并行输入为并行泳道后汇合 |
| staged_process 阶段流程 | 吞噬、ADC 作用、发育/感染阶段 | 3—6 个编号阶段一行（最多换行一次），同一对象跨阶段保持形态 |
| taxonomy_convergence 分类汇聚 | 方法学综述、技术分类、多策略汇聚到同一目标 | 每类一个模块，成员用括号线归到类标签，类标签汇聚箭头指向唯一结果节点 |
| workflow 研究流程 | 技术路线、实验设计、数据分析管线 | 输入 → 处理 → 读出 → 整合 → 结论；并行分支在整合步汇合 |
| hub_spoke 中心辐射 | 综述总览、多领域围绕一个主题 | 中心主题为轮毂，等权扇区/卫星模块环绕，各列成员 |
| multiscale 多尺度 | 组织语境下的细胞/分子机制 | 组织/器官语境 → 放大框到细胞 → 分子机制，用放大线连接 |
| comparison 对照 | 处理前后、正常/疾病、两种药物 | 对齐的并列面板，只改变差异元素 |
| cycle 循环 | 免疫循环、反馈环 | 站点环形排列，回流路径走外侧 |

“中央大细胞”只在主题本身是该细胞内部区室时成立；即使如此，也用泳道组织关系，而不是在细胞四周平铺彩色模块。先给标签和箭头留空间，再安排插画细节；控制每个区域密度，必要时用多面板，不能未经说明删科学内容。膜上受体、容器内物体的相交/包含是语义，不适用通用“不可重叠”规则。

### 版式计划（可选记录）

复杂图可把结构写成小型版式计划，供 `b2r.py render-plan --contract ... --plan ... --out ...` 编译 A/B 请求：`schema_version:1, title, purpose, aspect, architecture`（上表名称，1—2 个）、`regions`（每项 id、可选 label、position、contains 实体 ID、note）、`reading_order`，可选 `refined_stage`（只给 B 的语境铺陈）与 `notes`。**region.note 只写位置与需要的科学符号，不写关系**，关系全部来自 Contract；否则两处描述会互相冲突。命令会提示未放入任何区域的实体，并把 CONFLICTED 关系挡在请求之外。

### 实测边界（2026-10-12）

- 一次请求里逐条列出十几条关系时，模型最常丢失或错接药物干预端点。编译时把首尾相接的简单箭头合并成一条链、把抑制/中和/裂解前置，并要求干预物紧邻目标放置，能减少但不能消除这类错误。
- 用代码骨架图（schematic）作参考图生成，在本宿主上反而导致拼写错误和对象错位，不作为默认流程。
- 以已核对的 A 为参考生成 B，会基本复制 A 而不换风格，并引入拼写错误；A/B 应各自用同一请求正文独立生成后分别核对。

默认 Scientific 2D；复杂度和跨区域不构成立体理由。默认双图保持同一机制方向与分区，Refined 不通过添加分子或机制取得细节。用户另有风格或关键结构需要空间深度时，按 scientific-visual-styles.md 调整表达。

## 交给渲染与检查

只把这份 Brief 中与出图有关的内容组织为工具请求：标题/用途 → 风格段 → 版式结构与区域 → 关键交互 → 其余关系 → 对象表现（药物标记、抗体朝向）→ 准确标签 → 排除项。A/B 只替换风格段和 B 的语境铺陈，其余正文逐字相同。无需重复模板、背景报告和全部规则，也无需另起模型调用。

交付前按 SKILL.md 查看真实结果：对象、端点/方向、阶段、标签/数值及布局是否正确；双图分别对照这份 Brief，不能只互相比较而漏掉共同错误。复杂机制将关键关系收紧为 [Scientific Figure Contract](scientific-qa.md)，不重复完整规划。修改继承 Brief 与契约，仅更新用户要求的内容。可选记录契约在 host-image-workflow.md，普通绘图不用先填写。
